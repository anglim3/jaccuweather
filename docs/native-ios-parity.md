# Native iOS vs weather.janglim.cloud

Personal-use SwiftUI app on `ios/`. Same upstreams as the website after lockdown (no Cloudflare Worker, no Ventusky HTML proxy). Logic that must match the site is extracted from `public/app.js` + `build.js` into `ios/Jaccuweather/Resources/Logic/jaccuweather-logic.js` and run in JavaScriptCore.

| Web feature | Native status |

| Open-Meteo ensemble (`icon_seamless,gfs_seamless,ecmwf_ifs025`) + `normalizeEnsembleWeatherData` | **DONE** — `WeatherService` + JS normalize (mean / medianFloor WMO / derived precip probability) |
| Current conditions (temp, feels, humidity, wind, UV, pressure trend, dew) | **DONE** — Now tab |
| Sunrise/sunset arc | **DONE** — half-ellipse matches the site SVG; dot uses location-local sunrise/sunset + `utc_offset_seconds` and ticks each minute (gold by day, moon when the sun is down) |

Small and medium home widgets use the Horizon navy gradient, glass chips, and a serif place name. Lock Screen circular, rectangular, and inline accessories keep that hierarchy, with the same fill when the system shows a widget background. SF Symbols from the WMO code. No SVG or WKWebView |

## Native-only extras

Not website features. The table above stays the website parity list.

| Extra | Status |
|---|---|
| Lock Screen Live Activity and Dynamic Island | **DONE** — current place temperature, WMO condition, and place name on a compact navy Lock Screen banner. Compact Dynamic Island shows the temperature and an SF Symbol for the WMO code. The app starts one activity for the current place and updates that activity while the place stays the same. Switching places ends the previous activity and starts another, because the place id is fixed when the activity starts. The activity ends when there is no current weather. No push-to-start, no new App Group, no SVG or WKWebView |
| Local NWS alert notifications | **DONE** — a refresh that finds a new active alert id for the current place posts one local notification. The title carries Extreme, Severe, Moderate, or Minor; the body is the headline. Tapping it opens that alert’s detail. Settings has an on/off control and asks for permission once; the same ask can happen the first time a new alert is found. Posted ids stay in UserDefaults. No push server and no remote-notification capability. Debug builds can post one labeled sample from Settings or with `-alertSample 1` |
| Upcoming precipitation notifications | **DONE** — after a successful forecast refresh, if the current hour is dry and precipitation probability reaches 50% within the next six hours, the app posts one local notification. Rain, snow, or a generic precipitation title depends on the hour’s amounts. The body names the place and the local hour window. The place and start hour stay in UserDefaults so later refreshes stay quiet, and the notice is removed when that hour has passed or the forecast no longer shows the start. Settings has a separate on/off control and asks for notification permission the same way alerts do. The check uses the in-app forecast only. Tapping opens the Forecast tab, as does `jaccuweather://forecast`. No push server. Debug builds can post one labeled sample from Settings or with `-precipSample 1` |
| Overnight freeze warnings | **DONE** — after a successful forecast refresh, if tonight’s overnight low is at or below 32°F, the app posts one local notification. At or below 28°F the title is “Hard freeze tonight”; otherwise it is “Freeze warning tonight”. The body names the place and the expected low. The overnight is the daily minimum still ahead: before 08:00 local that is today’s minimum, and from 08:00 it is the next daily minimum. Settings has a separate on/off control that stays off until turned on, and turning it on asks for notification permission the same way alert notices do. The control states that this uses the forecast already loaded in the app and does not use a push server. The place and the local calendar day of that overnight stay in UserDefaults so a later refresh does not post the same night again. A later refresh removes the notice when that overnight has passed or the low is above 32°F. Tapping the notice opens the Forecast tab (`jaccuweather://forecast`). Debug builds can post one labeled sample from Settings or with `-freezeSample 1`. No push capability and no new App Group |
| High wind-gust local notifications | **DONE** — after a successful forecast refresh, if sustained wind or gusts in the next 24 hours reach 40 mph, the app posts one local notification. The stronger of the hourly mean wind and gust is used; when only one is present, that value is used. The first hour in that window at or above 40 mph is the one announced. Gusts use the title “Damaging gusts expected”; sustained wind uses “High winds expected”. The body names the place, the expected speed, and the place-local hour. Settings has a separate on/off control that stays off until turned on, and turning it on asks for notification permission the same way alert notices do. The control states that this uses the forecast already loaded in the app and does not use a push server. The place and that hour stay in UserDefaults so a later refresh does not post the same window again. A later refresh removes the notice when that hour has passed or the forecast no longer meets 40 mph. Tapping the notice opens the Forecast tab (`jaccuweather://forecast`). Debug builds can post one labeled sample from Settings or with `-windSample 1`. No push capability and no new App Group |
| App Intents / Siri and Shortcuts | **DONE** — Get Current Weather returns the place, temperature, condition, and feels-like from the last successful in-app forecast, and fetches again when that reading is older than 15 minutes. An optional favorite uses a saved place. Open Jaccuweather opens the Now tab and can switch to a favorite. A successful refresh donates the current-weather shortcut. Phrases: “What’s the weather in Jaccuweather” and “Open Jaccuweather”. No new App Group |
| Control Center | **DONE** — `OpenNowControl` in the existing widget extension. The gallery name is Open Jaccuweather. Tapping it runs `OpenNowIntent`, which brings the app forward and shows the Now tab for the place already loaded. The URL `jaccuweather://now` selects that same tab. When the existing App Group snapshot includes a temperature, the control label shows that reading and the place name. A free Personal Team cannot create the App Group container, so the label stays Open and the control still launches Now. No new App Group entitlement and no push |
| Share current conditions | **DONE** — Now tab toolbar control opens the system share sheet. The text is the place, temperature, feels-like, condition, today’s high and low when the forecast has them, and `jaccuweather://now`. Place-specific links are not used. No analytics or social SDKs |
| Favorites reorder | **DONE** — Location sheet **Reorder** shows drag handles when two or more favorites are saved. The new order is written to the existing UserDefaults `weatherFavorites` array. Tap a favorite to load that place. Swipe to remove. One favorite, or none, stays a plain list with no reorder control |
| Apple Watch companion | **DONE** — `JaccuweatherWatch` glance shows the place, temperature, feels-like or condition, and a WMO SF Symbol on the Horizon navy field, plus the next eight place-local hours (temperature, precipitation probability, rain or snow cue) and the next seven place-local days (weekday, WMO SF Symbol, high and low). Hours and days use Open-Meteo `utc_offset_seconds`, matching the iPhone’s location hour and today row. The iPhone pushes the current forecast with WatchConnectivity after a successful refresh, and includes an NWS summary (`alertTitle`, `alertSeverity`, `alertCount`) when active alerts are loaded. The glance shows a compact badge only when all three fields are present; it does not fetch alerts or invent a badge when they are missing. Under the temperature, one line shows today’s sunrise and sunset in place-local time. Shorter watches, including the 40mm, use tighter type so that line, the header, and the hour and day rows stay fully on screen. A 45mm face and larger keep the roomier sizes, and those columns widen so the card ends on a whole hour and a whole day. A fresh phone snapshot’s `sunriseISO` and `sunsetISO` are used when present; otherwise Open-Meteo daily sunrise and sunset for the place on screen. Complications stay temperature and condition. A reading under about 40 minutes old is shown as-is. Otherwise the Watch loads `api.open-meteo.com/v1/forecast` for the last saved coordinates, or Seattle when none are saved. Circular and rectangular complications show temperature and condition for the place the glance published. Personal Team cannot provision App Groups, so no App Group entitlement is added; the glance writes `watch-place.json` into the complication’s documents directory and the complication reads it there. Tapping a complication opens that place’s glance. The phone context also includes `favorites`, a JSON array of display name plus latitude and longitude, deduped by the same coordinate id as the iPhone favorites list and capped at 12. Places on the glance lists the city on screen plus those favorites. Picking one writes `watch-place.json` (`explicit`), reloads the complication, and uses the phone reading when it is still fresh for that place; otherwise Open-Meteo. An explicit pick stays ahead of a later phone city. No push and no Worker secrets |

## Honest leftovers (not code gaps vs the site)

| Item | Why it is not a merge blocker |
|---|---|
| Ventusky stays on the website | The iOS app does not embed it and does not link out from the Radar tab. |
| Google/Tomorrow species detail | Needs the owner’s **billing-capable** Google Pollen key (iOS-restricted). Blank keys → Open-Meteo, which is correct. |
| Places outside NOAA mosaics | The Radar tab says radar is unavailable. It does not substitute another imagery source. |
| Free Apple ID re-sign every ~7 days | Personal Team limit. Not an app bug. |
| ApexCharts / MathJax / Leaflet | Replaced by Swift Charts + methodology copy + MapKit. Scoring is the same JS. |
| Worker pollen rate-limit / same-origin | N/A off-Worker. Personal app is one user. |
| Preview Worker Google pollen | Unrelated; production website still uses Worker secrets. Native does not. |

Web Worker under `public/` is unchanged. Native calls stay on public upstreams (30s timeout, 429 retry, short forecast/geocoding cache). Production Worker secrets are not in the app.
